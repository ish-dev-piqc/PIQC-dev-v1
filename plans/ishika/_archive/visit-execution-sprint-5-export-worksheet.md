# Visit Execution Workspace — Sprint 5: Export pipeline ("worksheet" deliverable)

## Context

The VEW arc through Sprint 4c shipped a workspace where a coordinator can
review, edit, annotate, audit-trail, and resolve completeness gaps on
PIQC-drafted requirements. What's missing is the **funnel exit** — the
moment where the coordinator takes the polished worksheet *out* of PIQC
into their visit-day workflow.

Sprint 5 builds that exit:

1. Introduces "worksheet" as the deliverable noun (per `product_vew_workspace_vs_worksheet_model.md` — workspace = acting surface, worksheet = exit artifact).
2. Replaces the disabled `ExportPlaceholderButton` with a real PDF download.
3. Mirrors the SOTR export pattern (`sotr_get_draft_confidence_packet` + `buildDraftConfidencePacketCsv` + `downloadDraftConfidencePacket`) — three separately-testable layers, with a DRAFT disclaimer baked in.

PDF format chosen for v1 because:
- Print-ready + immutable + universally shareable
- Matches the "moment of lock-in" semantic of the worksheet deliverable
- `jspdf` + `jspdf-autotable` already in `package.json`
- DOCX can be added as Sprint 5.5 if coordinator feedback wants editable

## Naming / vocabulary (locked)

Per `product_vew_workspace_vs_worksheet_model.md`:

- Button label: **"Export worksheet"** (not "Export draft", not "Download")
- Filename: `<protocol_code>_<visit_name>_worksheet_draft_<YYYY-MM-DD>.pdf`
  - protocol_code falls back to `protocol_<id-prefix>` if no code is set
  - visit_name slugified (lowercase, dashes for spaces, non-alphanumerics dropped)
- PDF header attribution: "PIQC drafted · Visit worksheet · DRAFT"
- PDF footer disclaimer: "This worksheet was generated by PIQC as a draft aid. Final accuracy, compliance verification, source-document authoring, and approval occur outside PIQC in the site's designated process or system."
- Post-export button state: "Exported ✓" briefly (2 seconds) then reverts

## Decisions encoded for code review

1. **Three-layer split** (fetch / build / download) — mirrors SOTR's `exportApi.ts`. Allows the pure `buildVisitWorksheetPdf(packet) → jsPDF` step to be tested without touching the DOM or Blob API.
2. **PDF library**: `jspdf` for layout + `jspdf-autotable` for the workflow-ordered checklist table. Both already in deps.
3. **No client-side aggregation logic** — the RPC returns the packet pre-shaped. Build step is presentation-only. Keeps the consistency story honest: the same RPC could feed DOCX/CSV builders later.
4. **Defensive narrowing on the packet** — per Sprint 4c lesson: drop malformed rows at the API boundary rather than crash the build.
5. **Mock-mode synthesizes a packet** from `mockVisitWorkspace.ts` rather than disabling the export. Demos download a real PDF — that's the whole point of the moment.
6. **No optimistic updates** — export is a one-shot read; button state is local (idle → loading → success/error).
7. **Filename slug** — coordinator-readable, no UUIDs. Coordinators will reference the file in tickets and emails; the name has to be human-grokkable.
