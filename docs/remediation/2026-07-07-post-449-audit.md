## 3. Open items — ready-made specs

### 3.1 Result<T> hardening, Intake/Conduct (HIGH — Karl's area)

`updateProtocolRisk` (`src/lib/audit/intakeApi.ts:161`), `updateWorkspaceEntry` (`src/lib/audit/workspaceEntriesApi.ts:167`), `deleteProtocolRisk` (`intakeApi.ts:196`) still return `T | null`/`boolean`; callers swallow failures — `IntakeWorkspace.handleEdit` closes the form unconditionally (`IntakeWorkspace.tsx:152`), so a failed edit is silently discarded.

Spec: convert all three to the `Result` shapes already used by the create paths in the same files. Callers: IntakeWorkspace (edit + delete), AuditConductWorkspace (edit) — verified exhaustive. On failure: `setSaveError(result.error)`, do **not** close the form; delete failures get a `role="alert"` banner in list mode. Clear `saveError` in `cancel()`, `openAdd()`, `openEdit()`, and the audit-switch effect. Tests: convert `toBeNull()` error-path asserts in `intakeApi.test.ts`/`workspaceEntriesApi.test.ts` to Result asserts; new workspace tests per the `ReportDraftingWorkspace.test.tsx` mock pattern (edit failure keeps form + shows alert; success closes; stale error clears on reopen). Also: add `STAGE_NOT_IN_ADVANCEMENT_MAP` to the stale hint doc comment at `auditApi.ts:22-27`.

### 6.1 Committed migration history does not replay — prod has drifted

Three *already-applied* migrations fail when replayed from scratch. Each needed a local-only patch (NOT committed — the files on `main` are what prod's `schema_migrations` records; Roger owns the clean-up decision):

1. `20260618000200_protocol_guests.sql` — partial-index predicate calls `NOW()`, which Postgres rejects outright (not IMMUTABLE). This file **cannot ever have applied as written**, so what prod runs was created some other way and the file edited after the fact. Local patch: drop the `expires_at > NOW()` clause from the predicate.
2. `20260618000900_org_invite_protocol_assignments.sql` — `CREATE OR REPLACE FUNCTION accept_org_invite` changes the `RETURNS TABLE` shape, which Postgres refuses without a prior `DROP FUNCTION`. Local patch: add the DROP.
3. `20260704000200_chat_polish_v2.sql` — policies call a **single-arg** `user_can_access_protocol(uuid)`, but the only committed definitions (`20260618000400`, `20260618000800`) are two-arg `(uid, pid)`. Prod evidently has an uncommitted single-arg overload — a Studio hot-patch that never became a migration. Local patch: recreate the wrapper before the policies.
4. *(found during the §7 deploy)* `20260708000000_protocol_deliverables_schema.sql` was **repair-stamped "applied" in prod's ledger without its DDL ever running** — none of its tables existed. Almost certainly deliberate, to keep the then-ungated deliverable engine off prod. Resolved during the deploy (`migration repair --status reverted` + re-push); recorded here as the fourth drift instance for the reconciliation sweep.

Follow-up for Roger: pull the actual prod definitions (`supabase db dump --linked --schema public`), diff against the repo, and commit reconciling migrations so history replays. Until then every fresh local environment (and any future CI that replays migrations — worth adding once this is fixed) hits these three.
